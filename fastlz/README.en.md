## Overview

`fastlz.lua` is a **pure-Lua port** of the FastLZ compression algorithm with no
native dependencies. It was ported with AI assistance from the FastLZ C
implementation bundled by the lua-fastlz project (FastLZ 0.1.0, by Ariya
Hidayat, MIT licensed). Its data format is fully compatible with the lua-fastlz
C module:

- The compressed output starts with a 4-byte big-endian (network order) header
  holding the original length, followed by the raw FastLZ stream;
- Inputs smaller than 65536 bytes use level 1, otherwise level 2 (the same rule
  as the C version);
- Decompression detects level 1 / level 2 from the first stream byte, so it can
  decompress data produced by the C `fastlz_compress`, and vice versa.

Compatible with Lua 5.1 / 5.2 / 5.3 / 5.4 and LuaJIT (the bit-operation backend
is selected automatically).

```lua
local fastlz = require("fastlz")
local compressed = fastlz.compress(data)   -- returns nil on failure
local original   = fastlz.decompress(compressed)
```

## Compatibility testing

To verify format compatibility, this pure-Lua implementation was cross-checked
both ways against the **latest compiled build of the FastLZ repository**. The C
reference was built into a native `fastlz.dll` from the bundled
`build/fastlz.c` (FastLZ 0.5.0, the latest release of that repository):

1. **DLL compress → Lua decompress**: the C version compresses (with a 4-byte
   length header added) and `fastlz.lua` decompresses it;
2. **Lua compress → DLL decompress**: `fastlz.lua` compresses (with the 4-byte
   length header stripped) and the C version decompresses it.

A case passes only when both directions reproduce the original data.

### Test data

- **Random sample data**: 1000 samples under `samples/`, generated by the test
  tool and covering many lengths and a range of compressibility patterns;
- **Real Noita game files**: 2933 files under `real/`, 139,039,716 bytes
  (about 132.6 MiB), covering `.bin`, `.png_petri`, `.xml`, `.csv`, `.wak`,
  `.bmp`, `.lua` and more; the largest single file is 42 MB
  (`real/data/data.wak`).

### Results

**All tests passed** (full log in `real_test_report.txt`):

| Metric | Value |
| --- | --- |
| Total files | 2933 |
| Tested data | 139,039,716 bytes (about 132.6 MiB) |
| Passed | 2931 |
| Failed | 0 |
| Skipped | 2 (0-byte placeholder files; empty input cannot be meaningfully compressed) |
| Elapsed | about 10.8 s |

No failure occurred in either cross direction, on random samples or on real
game files.

> About non-identical compressed output: the C reference is FastLZ 0.5.0 while
> this port is based on FastLZ 0.1.0 as bundled by lua-fastlz. Their hash
> functions and boundary constants differ, so the compressed streams for the
> same input are usually not byte-identical; the **formats are still fully
> compatible** and both cross directions round-trip correctly, which is exactly
> what this test verifies.
>
> Testing also uncovered and fixed an out-of-bounds read on the Lua side at
> level 2 (reading 1–2 bytes past the end when a match runs to the end of the
> input); the fix substitutes `0` for those bytes.
